About this tool

SHA-512 is a cryptographic hash function from the SHA-2 family, defined in FIPS PUB 180-4 and published by NIST in 2001. It takes any amount of input data - a single character or a multi-gigabyte file - and produces a fixed 512-bit (64-byte) digest, normally written as 128 hexadecimal characters. Unlike encryption, hashing is a one-way operation: there is no key and no way to reverse a digest back into the original message.

This page computes SHA-512 entirely with the Web Crypto API built into your browser (crypto.subtle.digest). Your text never leaves your device and there is no server-side logging, which makes the tool safe for hashing API keys, license strings, tokens or any other sensitive value you only want a fingerprint of. The same input always yields the same digest, so you can compare hashes computed here with hashes produced by sha512sum on Linux, shasum -a 512 on macOS or Get-FileHash -Algorithm SHA512 in PowerShell - the hex strings will match exactly.

SHA-512 is used for integrity checks, digital signature schemes, password-derived keys (as part of HMAC and PBKDF2), blockchain address derivation and TLS certificate fingerprints. It is faster than SHA-256 on 64-bit CPUs because its internal word size matches the register width, while still offering a much larger output space. For new password storage you should still use a memory-hard KDF such as Argon2id or bcrypt rather than a bare hash, but for checksums and content addressing SHA-512 remains an excellent choice.

Input is hashed as UTF-8 text, so accented characters and emoji are converted to their multi-byte form before hashing - this is exactly what most server-side libraries do, meaning your digest will match theirs. If you need the shorter 256-bit variant, use the SHA-256 generator; for the legacy MD5 algorithm see the MD5 generator.
