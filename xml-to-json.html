XML to JSON Converter

Paste XML and get clean, indented JSON immediately. Attributes become @name keys, repeated elements become arrays, and stray text is preserved under #text. Everything runs locally.

What happens when XML meets JSON

XML and JSON both describe trees, but they disagree about how to do it. XML has attributes, mixed content, comments, processing instructions and namespaces; JSON has only objects, arrays, strings, numbers, booleans and null. A converter therefore has to make a set of judgement calls, and this tool makes them visibly rather than silently. Element names become object keys, nesting becomes nesting, and repeated sibling names automatically collapse into an array so that <tag>a</tag><tag>b</tag> becomes ["a","b"] instead of one key overwriting the other.

Attributes and text nodes

XML attributes are prefixed with an @ sign — <book id="1"> becomes {"@id": "1"} — which is the same convention used by popular libraries such as xml2js and fast-xml-parser, so the output drops straight into existing code. Character data that sits alongside child elements is placed under #text rather than being thrown away, and whitespace-only text between elements is discarded because it is almost always formatting noise from pretty-printed documents.

Why convert at all

JSON is the default format of web APIs and of every modern language's standard library, while XML still dominates SOAP services, RSS and Atom feeds, sitemaps, Office documents, Android layouts and countless government and banking interfaces. Converting to JSON lets you query the tree with ordinary property access, sort it, filter it, store it in MongoDB or Redis, and debug it with console.log. If the result needs to be flattened for a spreadsheet, the JSON to CSV converter handles that next step.

Reading errors instead of guessing

Malformed XML is reported with the position information the browser's own parser produces, so an unclosed tag surfaces as an explicit error message rather than a half-built object. Remember that XML is strict: every element must be closed, tags are case-sensitive, attribute values must be quoted, and a bare & must be written as &amp;. If your input fails, check those four things first. To go the other direction, the XML formatter will pretty-print a minified document, and the YAML validator does the same job for the YAML family.
