About this tool

A UUID (universally unique identifier, also called GUID in the Microsoft world) is a 128-bit label written as 32 hexadecimal digits in five dash-separated groups: 8-4-4-4-12. Version 4 UUIDs are generated from a cryptographically secure random number generator; the 13th hex digit is always "4" and the 17th is one of 8, 9, a or b. With 122 random bits, the chance of a collision is vanishingly small — you would need to generate about 2.7×1018 of them before a 50% chance of a single duplicate. Version 7 UUIDs, standardised in RFC 9562, put a 48-bit Unix millisecond timestamp in the most significant bits, so they sort chronologically — ideal as database primary keys because they avoid the index fragmentation caused by random v4 keys. This generator uses crypto.getRandomValues() when available and falls back to Math.random() only if not. Everything is computed in your browser: no UUID is ever sent to a server, so they are safe to use as API keys, database IDs, idempotency tokens or test fixtures.

When should I use which version?

Use v4 for tokens, session IDs, request IDs and anything that must be unguessable or where ordering does not matter. Use v7 for database primary keys and log correlation IDs, because the timestamp prefix keeps B-tree inserts sequential and lets you sort records by ID to approximate creation order. Never use a UUID as a security token that must remain secret if you print it publicly; generate it with a CSPRNG (which this tool does) and treat it as a public identifier.
