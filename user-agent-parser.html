What is a User-Agent string?

    
Every time a browser, app or bot requests a web page it sends a User-Agent (UA) header. That short line of text tells the server which browser is calling, which version it runs, which operating system and device it is on, and which rendering engine produced the page. The UA evolved in the mid-1990s alongside the first Netscape releases, when sites needed a cheap way to serve different markup to different browsers. Almost thirty years later the same header is still there, carrying a small amount of historical luggage: most strings begin with Mozilla/5.0 even in Chrome, Edge or Safari, purely for backward compatibility with 1990s sniffing code.

    
This parser breaks the string into its meaningful parts. It looks for the browser token and version (Chrome, Firefox, Safari, Edge, Opera, Samsung Internet, and the Chromium-based family), then detects the operating system from markers such as Windows NT 10.0, Mac OS X 14_5, Android 14 or iPhone OS 17_2. It also recognises the two mainstream engines — Blink/WebKit, reported by the AppleWebKit/537.36 token, and Gecko, reported by Gecko/20100101 — and finally guesses whether the device is a desktop, tablet, phone, or an automated crawler.

    
Why you would decode a UA string

    
    
      
  • Debugging reports. A user says "the layout breaks on my machine" — ask for the UA from navigator.userAgent and you immediately know their exact browser and OS build.
    • 
      
  • Reading access logs. Server logs store the raw string; this tool turns those cryptic tokens into a readable summary you can paste into a bug tracker.
    • 
      
  • Bot filtering. Crawlers, scrapers and SEO tools identify themselves in the UA. Spotting Googlebot, bingbot or curl tells you whether a hit is real traffic.
    • 
      
  • QA test matrices. Collect the UAs of the devices you actually care about, then use them to configure emulation in DevTools or Playwright.
    • 
    

    
Accuracy caveats you should know

    
A UA string is self-declared and freely spoofable, so treat the output as a strong hint rather than ground truth. Browsers have also deliberately frozen parts of the header: Chrome reduced the platform detail it exposes (User-Agent Reduction) and recommends feature detection with navigator.userAgentData instead. iOS Safari inside a third-party app often reports a WebView UA that omits the host app name. And some strings are genuinely ambiguous — Edge on macOS and Chrome on macOS differ only by a couple of tokens, so a heuristic parser occasionally guesses wrong. If you need certainty, prefer capability detection in the code you write and use the UA only for analytics and support triage.

    
Privacy

    
Everything here runs in JavaScript on your own machine. The string you paste is never uploaded to a server, which matters when the UA comes from a customer ticket or an internal log file. Close the tab and the data is gone. If you also need to decode tokens, try the JWT decoder; for encoding strings into a URL safe form see the URL encoder.
