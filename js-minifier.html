About this tool

Shipping smaller JavaScript means faster page loads, lower bandwidth bills and better Core Web Vitals scores. A conservative minifier that removes comments and whitespace typically cuts file size by 20-40% with zero risk of changing behaviour — unlike aggressive mangling minifiers which rename variables and can break code that relies on names.

This tool takes the safe route: it strips block and line comments, removes trailing and leading whitespace, deletes blank lines, and reports the before/after size and percentage saved. Because it never renames anything, the minified output is functionally identical to the input and remains debuggable if you need to inspect it.

Everything runs locally, so proprietary or unreleased code stays on your machine. For production pipelines you should still use a battle-tested minifier such as Terser or esbuild; this tool is ideal for quick one-file shrink jobs, snippets, and cases where you want predictable, mangle-free output.

Tip: paste your code, click Minify, then copy the result with one click. Repeated runs are idempotent — minifying already-minified code is harmless.

FAQ

Does it rename variables?

No — it only removes comments and whitespace, so behaviour is guaranteed unchanged.

Can it break my code?

It uses conservative transformations only. Code with URLs containing // inside strings on a line is the one edge case to double-check.

What size savings can I expect?

Typically 20-40% for hand-written code; already-minified code shrinks little.
