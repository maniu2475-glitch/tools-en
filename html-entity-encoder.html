HTML Entity Encoder & Decoder

Escape text so it can be safely pasted into HTML, or turn a block full of &amp; and &lt; back into readable characters. Everything runs locally in your browser.

About this tool

HTML treats four characters as markup: the ampersand, the less-than sign, the greater-than sign and the quote characters. If you paste user-generated text containing any of them straight into a page, the browser will try to parse them as tags or as the start of an entity, which is how comment sections break their own layout and how stored cross-site scripting bugs begin. Encoding those characters into named references such as &amp; and &lt; makes the text inert, and the visitor still sees exactly what you typed.

This tool encodes in two passes you can pick from in the output settings: a minimal mode that touches only the five markup-significant characters, and a broad mode that also converts every non-ASCII character into a numeric reference. The broad mode is what you want when a template, an email client or a legacy database mangles UTF-8, because numeric references are pure ASCII and survive almost any code page. The minimal mode is friendlier to read and keeps files smaller, so it is the better default for modern UTF-8 pages.

Decoding goes the other way and understands both named entities (the full HTML5 list including &nbsp;, &mdash;, &hellip; and the Greek letters) and numeric ones written in decimal or hexadecimal, such as &#169; and &#xA9;. Unknown entity-looking sequences are left untouched instead of raising an error, so you can decode a messy scraped fragment without losing the parts that were never valid entities in the first place.

Nothing is sent to a server: the conversion is a handful of regular expressions running against the textarea in front of you, which is why it works offline and why it is safe for confidential copy. If you are preparing user input for storage, remember that HTML encoding protects you only when the string is later inserted into HTML context - attribute contexts, JavaScript string contexts and SQL queries each need their own escaping, and this page is not a substitute for a proper sanitiser on the server.
