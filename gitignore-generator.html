Gitignore Generator

Build a ready-to-use .gitignore file in seconds. Select your stack below and the rules are merged and de-duplicated for you.

About this tool

A .gitignore file tells Git which files and folders never to track or commit. Getting it right the first time prevents the classic mistake of committing node_modules/, virtual environments, build output or a .env file that contains real credentials — mistakes that are painful to undo once they are in your commit history.

This generator merges several curated rule sets. Each rule is a glob pattern: a bare name like dist matches any file or directory with that name at any depth, a trailing slash (build/) restricts the match to directories, and a leading slash (/vendor) anchors the pattern to the repository root. The generator de-duplicates overlapping patterns so the output stays readable instead of turning into a wall of repeated lines.

Because ignores are layered, rules added later in the file do not override earlier ones unless you use a negation with an exclamation mark, for example !important.log to re-include a single file that a broader rule excluded. If a file is already tracked, adding it to .gitignore has no effect — you must first run git rm --cached <file>, then commit.

Everything runs locally in your browser: nothing you type or select is transmitted anywhere. Copy the result into a new .gitignore at the root of your repository (feature branches can also have their own), and commit it together with your first source files so collaborators pick up the same rules automatically.
