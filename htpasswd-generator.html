htpasswd Generator

Create an .htpasswd entry

Generate a line you can paste straight into an Apache or Nginx .htpasswd file. Hashing happens locally; the password never leaves your device.

—

Apache HTTP Server protects directories with HTTP Basic authentication: a .htpasswd file holds one line per user in the form username:hashed_password. Creating that line by hand is impossible for bcrypt, because bcrypt passwords embed a random salt and a cost factor. This generator produces ready-to-paste entries without you having to install htpasswd, spin up a Linux shell, or upload credentials anywhere.

The recommended format is bcrypt ($2y$), produced by the bcryptjs library with a cost factor of 10. bcrypt is deliberately slow, so brute-force attacks against a stolen .htpasswd file become expensive; the same password hashed twice yields two different lines because the salt is random. The SHA-1 option produces the legacy {SHA} format that Apache has supported since version 2.2 - it is still useful for older servers and for Nginx auth_basic_user_file configurations that do not understand bcrypt.

Both hash functions are computed in your browser and the password is never transmitted. Paste the resulting line into your .htpasswd file - typically next to a .htaccess containing AuthType Basic, AuthName "Restricted", AuthUserFile /path/.htpasswd and Require valid-user. Since a bcrypt entry contains $ characters, make sure your editor does not interpret them and keep the file outside the web root.

Frequently asked questions

Is it safe to type my password into this page?

Yes as far as the network goes - the hashing is done by JavaScript in your tab and no request is sent with your password. That said, for production secrets prefer a local command such as htpasswd -B on your own server.

bcrypt or SHA-1 - which should I use?

bcrypt. It is salted and intentionally slow, which makes offline cracking far harder. Choose SHA-1 only when your server software cannot handle $2y$ entries.

Why does my entry start with $2y$ instead of $2a$?

Apache and Nginx expect the $2y$ variant prefix for bcrypt; bcryptjs emits $2a$, which is functionally identical, so the prefix is rewritten to $2y$ for maximum compatibility.

Where do I put the generated line?

Append it to the file referenced by AuthUserFile (Apache) or auth_basic_user_file (Nginx). One user per line, no spaces around the colon.

Can I add several users to one file?

Yes. Generate one line per user and append each on its own row. Duplicate usernames are not allowed - keep only the newest line for a given name.
