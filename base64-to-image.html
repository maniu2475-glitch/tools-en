What a Base64 image actually is

A data URI embeds a whole file inside a string: data:image/png;base64,iVBORw0KGgo.... The part before the comma is a media type declaration, the word base64 says how the bytes were encoded, and everything after the comma is the file itself translated into the 64-character alphabet A-Z a-z 0-9 + / with = used as padding. Base64 exists because text channels — HTML attributes, CSS url(), JSON strings, email bodies — cannot safely carry arbitrary binary. Each group of three bytes becomes four characters, so the encoded string is about 33 percent larger than the original file.

When embedding beats a separate request

Inlining removes one HTTP request per image, which matters for tiny assets such as icons, spacer pixels, SVG logos and CSS gradients, and it guarantees the image renders even if the host path changes. The cost is that inlined images cannot be cached separately, they block the parsing of the stylesheet or HTML that contains them, and they are repeated in full every time the containing file is served. As a rule of thumb, inline anything under a few kilobytes and keep photographs and screenshots as separate files — and never inline an image that appears more than once on a page.

Reading the preview honestly

This page decodes entirely in the browser: the string never leaves your machine, which is why it is safe for screenshots of invoices, IDs or internal dashboards. The decoder sniffs the media type from the first bytes when the data URI does not declare one, because Base64 itself carries no format information — a JPEG and a PNG encode to indistinguishable-looking strings. If the preview area refuses to appear, the bytes are not an image: a truncated string, a missing +, or a newline inserted by an email client will all produce invalid data rather than a broken-looking picture.

Going the other way

The upper panel decodes, and the lower panel encodes a file you pick. Use it to build a CSS icon or a mail-signature logo, then check the resulting length before pasting into a style attribute. For raw text rather than files the Base64 encoder is simpler, the image compressor will shrink a photograph before you decide to inline it, and the image resizer is the right first step when a screenshot is too large to embed at all.
